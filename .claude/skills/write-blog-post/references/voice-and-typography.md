# 語氣與繁中排版

## 語氣

寫給坐在旁邊的同事聽。

| 要 | 不要 |
|---|---|
| 第一人稱：「我這邊是 Next.js 16」 | 無主詞的公文體：「本文將介紹…」 |
| 口語連接詞：所以、結果、後來、反正、其實 | 制式排比：首先…其次…再來…最後… |
| 直接說不知道：「這段我沒查到原因，先記著」 | 假裝全都懂 |
| 有立場：「我不會在 production 這樣接」 | 每個方案各給一段，最後不表態 |
| 承認踩坑：「我第一次是這樣寫的，然後 build 就掛了」 | 每一步都順利成功 |
| 不確定就標一次：「應該是 effect 順序的關係，但我沒驗」 | 每句都 hedge（可能、或許、大概、某種程度上） |

長度隨內容走，不要湊。500 字的筆記是完整作品，不是半成品。

## 台灣用語

技術名詞保留英文原文，不要硬翻。要中文的時候用台灣慣用詞：

| 用 | 不用（中國用語） |
|---|---|
| 軟體 / 硬體 | 软件 / 硬件 |
| 程式 / 程式碼 | 程序 / 代码 |
| 執行緒 | 线程 |
| 伺服器 | 服务器 |
| 預設 | 默认 |
| 變數 / 函式 / 物件 | 变量 / 函数 / 对象 |
| 檔案 / 資料夾 | 文件 / 文件夹 |
| 網路 | 网络 |
| 資料庫 | 数据库 |
| 快取 | 缓存 |
| 介面 | 接口 |
| 最佳化 | 优化 |
| 套件 / 相依套件 | 包 / 依赖包 |
| 儲存庫 | 仓库 |
| 重新啟動 | 重启（口語可用，正式段落用完整詞） |

## 排版

- **中英文之間加一個半形空格**：`用 Astro 做靜態站`，不是 `用Astro做靜態站`。
  中文與半形數字之間也加：`Next.js 16 這版`、`大概 30 秒`。
- 標點用**全形**（，。：；「」（）），但以下保持半形：程式碼、指令、路徑、版本號、URL。
- 全形標點前後**不要**再補空格：`build 完成，接著部署。`
- 引號用「」，內層用『』。不要用英文的 " "。
- 破折號少用；中文技術文章裡它常常是「我懶得想連接詞」的替身，能拆成兩句就拆。

## 翻譯腔

這些是中文技術文章最常見的 AI／翻譯味來源，看到就改：

| 翻譯腔 | 改成 |
|---|---|
| 透過…的方式來進行… | 用…做… |
| 做一個 restart 的動作 | restart |
| 在…的部分 | （直接刪，講那個東西本身） |
| 對…進行設定 | 設定… |
| 是一個非常強大的工具 | （講它到底解決你什麼問題） |
| 值得注意的是 | （直接講那件事） |
| 隨著…的快速發展 | （刪掉整句） |

## 句子節奏

連續三句以上長度差不多，讀起來就會像機器。破解方式是**搬動字詞，不是加字**：
把一個長句拆成兩句，或把兩個短句併起來，或刪掉一個子句。
不要反過來全部改短 — 通篇短句是同一個毛病的另一面。
