# 語氣與繁中排版

規則來自站上 83 篇的實際寫法，範例全部是真的從文章裡抄出來的。

## 敘事人格

這個站的敘事者是**一個會在事後笑自己的工程師**。他不是在教學，是在講剛剛發生的事。
三個必備動作：

1. **先自信，再打臉。** 「那天晚上我覺得自己是天才。」→（兩節之後）→「天才當場變兇手。」
   把得意寫出來，翻車才有落差。只寫正確答案的文章沒有人要看。
2. **對讀者眨眼。** 「理論很漂亮。我又覺得自己是天才了（你看出問題了吧）。」
   讀者比你早一步看到坑，讓他享受這件事。
3. **自嘲但不自貶。** 「原因蠢到我想找個地洞鑽進去」可以；「我真是個爛工程師」不行。
   蠢的是那個 bug 的形狀，不是你這個人。

## 句子

| 要 | 不要 |
|---|---|
| 第一人稱：「我手邊有台 Lenovo 平板」 | 無主詞的公文體：「本文將介紹…」 |
| 口語連接詞：所以、結果、後來、反正、其實、欸 | 制式排比：首先…其次…再來…最後… |
| 單句成段當節拍器：「天才當場變兇手。」 | 每段都三到四句，均勻得像機器 |
| 直接說不知道：「這段我沒查到原因，先記著」 | 假裝全都懂 |
| 有立場：「我不會在 production 這樣接」 | 每個方案各給一段，最後不表態 |
| 不確定就標一次：「應該是 effect 順序的關係，但我沒驗」 | 每句都 hedge（可能、或許、大概、某種程度上） |
| 句尾語助詞偶爾放一個：「說出來只要一行啊」 | 每句都放，會變過度口語 |

連續三句以上長度雷同就會像機器。破解方式是**搬動字詞，不是加字**：
把長句拆兩句、把兩個短句併起來、或刪一個子句。不要反過來全部改短 ——
通篇短句是同一個毛病的另一面。

## 標點與排版

- **破折號 `——`（全形雙破折號）是這個站的主節奏**，82/83 篇在用。三種用法：
  接轉折（「邏輯看起來是對的啊——單元測試也沒爆」）、
  接自嘲（「而且比較慘的是，腳本是我自己寫的」前面那個 `——`）、
  接補充定義（「`onDocumentUpdated`——只在文件『被更新』的時候 fire」）。
  不要用 `--`、`–`、`—`（單破折號）。
- **直角引號「」**，內層用『』。不要用英文 `" "`。
- **粗體一段最多一處**，放那句你希望讀者只記得這句的話。
- **不要用 markdown 表格** —— 全站 0 個。要對照就條列，或直接寫成兩句話。
- 中英文之間、中文與半形數字之間加一個半形空格：`用 Capacitor 包成 Android 殼`、`長到 1205 行`。
- 全形標點前後不要再補空格：`裝上去了，重測登入……還是彈回 landing。`
- 標點用全形，但程式碼、指令、路徑、版本號、URL 內部維持半形。

## 台灣用語

技術名詞保留英文原文，不要硬翻（站上 `trigger`、`fallback`、`guard`、`callsite`、`deep link`
全部直接用英文）。要中文的時候用台灣慣用詞：

| 用 | 不用 |
|---|---|
| 軟體 / 硬體 | 软件 / 硬件 |
| 程式 / 程式碼 | 程序 / 代码 |
| 執行緒 | 线程 |
| 伺服器 | 服务器 |
| 預設 | 默认 |
| 變數 / 函式 / 物件 | 变量 / 函数 / 对象 |
| 檔案 / 資料夾 | 文件 / 文件夹 |
| 網路 | 网络 |
| 資料庫 | 数据库 |
| 快取 | 缓存 |
| 介面 | 接口 |
| 最佳化 | 优化 |
| 套件 / 相依套件 | 包 / 依赖包 |
| 儲存庫 | 仓库 |

## 翻譯腔

中文技術文章最常見的 AI／翻譯味來源，看到就改：

| 翻譯腔 | 改成 |
|---|---|
| 透過…的方式來進行… | 用…做… |
| 做一個 restart 的動作 | restart |
| 在…的部分 | （直接刪，講那個東西本身） |
| 對…進行設定 | 設定… |
| 是一個非常強大的工具 | （講它到底解決你什麼問題） |
| 值得注意的是 | （直接講那件事） |
| 隨著…的快速發展 | （刪掉整句） |
| 綜上所述 / 總結來說 | （刪掉，直接講結論） |
