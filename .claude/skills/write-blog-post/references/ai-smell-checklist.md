# 交稿前檢查表

**一項一項跑。** 合成一次掃會漏掉。
單一條命中不代表什麼，**成群出現才要重寫**。

## 站台規則（先跑這段，這些是硬錯）

1. **`## 前言` / `## 環境`**　站上 83 篇一篇都沒有。有的話刪掉，內容併進開場或正文。
2. **`####`**　全站 0 個。有第四層標題就往上併。
3. **markdown 表格**　全站 0 個。改條列或改寫成句子。
4. **裸 code fence**　每個 ``` 後面都要有語言標記，否則 Shiki 渲染成單色 plaintext。
5. **code fence 太多**　全站只有 16/83 篇有 fence。問自己每一段是不是真的是轉折，
   不是的話改行內 `` `code` ``。
6. **標籤**　2–5 個、全部在 `CLAUDE.md` 的 30 個受控清單內、沒有自創。
7. **收尾三件套**　`## 收尾`（或 `## 我學到的三件事`）→ 自嘲轉身句 → 斜體時間戳。
   provenance footer 只有在你真的有 sha 的時候才加。
8. **篇幅**　內文超過 90 行（中位數 45）就回頭看有沒有哪節沒有自己的轉折。

## 結構

9. **開場是題目導覽嗎**　「在當今的前端開發領域…」／「PostHog 是一個…」→
   改成從你真正遇到的情況開：錯誤訊息、數字、當下的卡點。
10. **開場公式化**　又一次「你有沒有過那種…的經驗？」？這個句型站上已經用了 28 次。
    這篇換自白式或直接丟現場。
11. **沒有誤診段**　全篇一路直達正確答案？→ 補上你先信了什麼、改了什麼、發了什麼版才發現不對。
    **這是讀者最信的部分**，也是這個站最好看的幾篇的共同點。
12. **假裝成散文的條列**　整段其實是「第一…第二…第三…」→
    要嘛老實條列，要嘛寫成有論點的段落。
13. **每層都在摘要**　每節開頭預告、中間講、結尾再總結一次 → 只在該待的層級講一次。
14. **每節等長**　每個 `##` 都剛好三到四段 → 依有趣程度重新分配，讓你卡最久的那節最長。
15. **結尾殘留**　「總結來說…」「未來展望…」「希望這篇對你有幫助」→ 刪。內容講完就停。

## 內容

16. **沒有失敗**　全篇每一步都成功 → 補上你先試了什麼、哪裡壞掉、下次會跳過什麼。
17. **沒有立場**　比較了幾個做法卻不給建議 → 給推薦，並附上「什麼情況下我會改變主意」。
18. **自創名詞**　文章中途發明了一個詞（「設定漂移症候群」）→ 用白話講，或用業界既有名詞。
19. **程式碼沒跑過**　出現 `foo`、`my_service` 這種沒執行過的範例 →
    換成實際跑的那一份，或明講這是示意。
20. **數字沒條件**　貼了效能數字卻沒寫機器、版本、資料量、跑幾次 → 補條件，或拿掉。
21. **具體資訊是真的嗎**　版本號、路徑、參數名、錯誤訊息、commit sha 全部要是實際看到的。
    **不確定就去查或留 TODO，絕對不要編。** 自信地講錯是最高等級的破綻。

## 表面

22. **AI 客服殘留**　「讓我們開始吧」「很棒的問題」「希望對你有幫助」→ 刪。
23. **廢話密度**　同樣內容能不能用一半篇幅講完？「在這個快速變遷的時代」「值得注意的是」
    資訊量為零 → 刪。
24. **裝飾性格式**　emoji 當項目符號、粗體小標滿天飛、每個清單都剛好三點 →
    粗體一段最多一處，清單長度照事實走。
25. **破折號用對了嗎**　是全形 `——` 嗎？是拿來接轉折／自嘲／補充，
    還是只是「我懶得想連接詞」？後者拆成兩句。
26. **翻譯腔**　跑 `voice.md` 的翻譯腔表。
27. **句子節奏**　有沒有連續三句以上長度雷同。
28. **唸出來**　文法對但沒人會這樣講話的句子，用講話的語序重寫。
