[VanishWhisper](https://vanishwhisper.web.app) 是我做的網頁聊天室。不用註冊，打開就能跟人說話，訊息讀完會消失，內容從頭到尾加密，伺服器看不懂。我是後端工程師，這是我第一個前端 side project，程式幾乎都是 agent 寫的，我負責決定要做什麼、不做什麼，然後拿手機戳戳看有沒有壞。

4 月 27 日晚上，加密聊天和讀後消失做好了。之後兩天，我自己在用，也傳了幾則訊息給朋友。

4 月 29 日晚上，我想到一件事：換手機怎麼辦。

VanishWhisper 沒有帳號。每台裝置第一次打開，就拿到一個匿名的身分，同時在瀏覽器裡產生一組自己的鑰匙，私鑰只存在那台裝置上。換一支手機，等於換了一個人，舊的對話全部打不開。

要提這個需求的時候，我才意識到，我對這個 app 的加密到底怎麼運作，其實說不出來。我知道有端對端加密，知道私鑰在瀏覽器裡，細節從來沒仔細看過，全是 agent 寫的。我理所當然地想，換裝置就是把私鑰搬過去，就這樣跟 agent 說了。

agent 給的做法不一樣。

每段對話本來就有一把自己的 AES 鑰匙，訊息用它加密，再用兩個人各自的公鑰包一份，存在資料庫裡。要搬家的時候，舊手機用自己的私鑰把每段對話的那把 AES 鑰匙解開，立刻用新手機的公鑰重新包一份，寫回去，把對話裡原本屬於舊手機的那個位子換成新手機。對話的鑰匙沒有換，所以對方那份還能用，什麼都不必做，只會看到我的身分編號變了。私鑰從頭到尾待在原本的裝置上，哪裡都沒去。

操作上是這樣的：在新手機上找到自己的身分編號，貼進舊手機的搬家頁。舊手機抓到新手機的公鑰，算出一串指紋，我要去新手機的個人頁對一下，兩邊一樣才按確認。之後一段一段對話依序搬，有進度條，中途斷掉，重跑會從沒搬完的地方接下去。

還有一個收尾。舊訊息上記的寄件人，還是舊手機的身分。新手機第一次打開某段對話時，會把那些訊息的寄件人改成自己，否則「這則是我發的」會認錯，自己的訊息也收不回來。資料庫只在舊身分已經不在這段對話裡之後，才准做這種改寫。

這套做法有個前提：舊手機要還在、還能開。手機掉了，就沒有人能把鑰匙解開再包一次。

看完這個解法，我坐在那邊想了一分鐘。自己做的東西用了兩天，底層怎麼運作完全不知道，然後 agent 用一個比我想的更漂亮的方式把問題解掉了。這個感覺很奇妙，有點荒謬，也有點爽。

搬家那個晚上十點三十一分上線。十六分鐘後，又補了一筆，讓我幫每個人取的暱稱也能跟著搬過去，那件事我在[這篇](https://southern-light.dev/blog/vanishwhisper-names-cross-devices/)寫過。程式碼在 [GitHub](https://github.com/redtear1115/vanishwhisper)，其他作品在[作品集](https://southern-light.dev/works/)。

先不說了，我得去把那段搬家的程式，從頭到尾自己讀一遍。
