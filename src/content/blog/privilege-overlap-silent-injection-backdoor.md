你有沒有想過,真正危險的後門長什麼樣子?不是電影演的那種一堆終端機跑綠字,是**一行小到 reviewer 會直接按 approve 的 diff**。

前陣子看到一則新聞:某個城市的一所學校,委員會在市長就任前,把「參與某個特定社團」新增為「特殊市長獎」的評選標準之一;市長就任之後,在畢業典禮上親自把這座獎頒給了自己的孩子,而孩子正是靠這條新增的管道拿到資格的。沒有人偽造文件,也沒有證據指出評選標準是為了誰而加——只是剛好有一個人,同時站在「這個獎項名義上的最高權威」跟「得獎者家屬」兩個位置上。資安圈有個名字給這種結構,叫 **confused deputy problem**:一個被賦予高權限的角色,在完全合法合規、查不到任何一步「違規」的前提下,被引導著替別人(甚至替自己)做了它本來不該做的事。

這篇我想從攻擊者的角度想一次這個問題——不是教怎麼打,是想清楚**這種漏洞為什麼防不勝防**,順便講講我們在 infra 上實際擋過的方法。

## 如果我是那個「剛好身兼兩職」的人

假設我同時是公司內部 feature flag 服務的管理者,也是計費系統(entitlement service)的其中一個 on-call admin——這兩個系統本來八竿子打不著,一個決定誰看得到哪個實驗功能,一個決定誰付了錢、該有哪些權限。但因為公司規模不大,權限給得比較鬆,我剛好兩邊都有寫入權。

我不會寫一段「if user == me then grant_admin()」這種一看就有鬼的 code——這種東西 code review 一定被抓包。我會做的,是找一個**兩個系統交界處、平常沒人特別關注的欄位**。比如 feature flag 服務裡有個 `internal_qa_allowlist`,設計初衷是讓 QA 帳號可以免費測付費功能,不用真的走計費流程。這個欄位平常變動很少,diff 也很小,通常是「新增一個 QA 帳號」這種一行 commit,reviewer 掃過去就過了。

我要做的,只是把自己的帳號 ID 加進這份 allowlist,而 commit message 寫得跟平常任何一次維護一樣平淡:「add QA test account for billing regression」。時間點也不會挑在有人盯著看的時候——我會挑在一次比較大的 release 前後,那幾天的 diff 量本來就大,我這一行會被淹沒在一堆真正重要的改動裡。

這就是「注入」最危險的形式:**它不是被藏起來,是被放在一個看起來完全正常、而且平常真的沒人細看的地方。**跟市長獎那個案例邏輯一模一樣——沒有人偽造成績,只是剛好有一個管道,平常審查得比較鬆,而剛好有人同時握有進出這個管道的兩把鑰匙。

## 這類漏洞為什麼特別難防

第一,它不違反任何單一系統自己的規則。feature flag 服務允許管理者新增 allowlist 項目,這是它的正常功能;計費系統信任 flag 服務吐出來的權限判斷,這也是它的正常設計。壞事發生在**兩個系統互相信任的邊界上**,而邊界本身通常沒有 owner。

第二,權限重疊這件事,常常不是設計出來的,是**組織長大之後自然長出來的**。一開始團隊小,一個 infra 工程師身兼三個系統的 admin 很正常;等公司大了,權限沒有跟著重新盤點,舊的重疊就留在那裡,變成沒人記得、也沒人特地去查的攻擊面。

第三,也是最麻煩的一點:**這類異動通常完全在合法權限範圍內。**它不會觸發「未授權存取」的告警,因為存取本來就是授權的。要抓到它,你要看的不是「這次操作有沒有權限」,而是「這個人為什麼同時有這兩個權限」。

## 我們後來怎麼擋

三件事,沒有一件很花俏,但擋住的就是這種問題:

**職責分離(separation of duties)**——凡是會影響「誰能拿到什麼」的系統,管理權限跟受益資格分開授權給不同人,同一個人不該同時能改規則、又剛好在規則的受益範圍裡。

**設定當 code 治理**——像 `internal_qa_allowlist` 這種欄位,一律走 GitOps,強制兩人 review,而且 review 規則裡明訂:「新增自己或近親帳號」要額外標記,不能靠 reviewer 自己眼尖抓到。

**對交界欄位做異常偵測,不只對存取做**——我們後來加了一條規則:任何橫跨兩個信任邊界的欄位(像這種同時影響 flag 服務跟計費系統的),異動會額外發一份 diff 到一個獨立的稽核 channel,不進正常 PR 的噪音裡,而且觸發規則不是「有沒有異動」,是「異動的人是不是剛好也在受益名單附近」。

可遷移的教訓是:**權限之間的重疊本身就是攻擊面,不管重疊是被誰刻意造出來的,還是組織長大之後自然長出來的。**你不能只稽核單一系統合不合規,得去問「有沒有人同時站在裁判跟球員兩個位置上」。

先不說了,我得去把公司內部那些「這個人身兼兩個系統 admin」的清單重新拉一次——上次拉是一年前的事了,我猜現在肯定又長出新的了。
