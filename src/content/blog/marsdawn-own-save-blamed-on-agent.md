[MarsDawn](https://marsdawn.southern-light.dev) 是我做的 Mac 版 Markdown 編輯器，左邊寫、右邊看預覽。我最常拿它看 agent 寫的文件。agent 改了我開著的檔案，MarsDawn 會自己載入新版本；新版本要是蓋到我剛打的字，視窗上方會跳出一條提示：「另一個 App/Agent 更改了這個檔案。先前的內容已保留。」

下一步想做的，是把 agent 改了哪幾段標出來。11 月 6 日凌晨三點十一分，這個功能的計畫寫好了，列了六件事等我決定，我沒回覆就不動工。agent 審這份計畫時，沿著「外部變更」那段程式往下讀，不到一分鐘，另外開了一張票。

票上寫的是一件還沒有人碰過的事。MarsDawn 會自動存檔，存完，負責盯檔案的那段程式發現檔案變了，等 200 毫秒再讀回來。讀回來時它只比一件事：檔案裡的字，跟編輯器裡的字一不一樣。如果我在這 200 毫秒裡又打了字，兩邊就對不上，我自己剛存的那一份，會被當成別人改的。

接下來三件事一起發生。剛打的字從編輯器消失，游標跟著跳，提示列說有別的 App 或 agent 改了檔案。字沒有真的丟，按還原拿得回來，前提是我得先發現少了一行。

兩分鐘後，agent 在票上補了七個程式位置，一條一條接起來，結論是這條路走得到，也沒有防護。唯讀的文件早就擋住了這種情況，可以編輯的文件沒有。不過它開頭寫的還是「尚未重現」。它先寫了一個測試，交給另一台 MacBook Air 上的測試員跑。

三點三十二分，結果回來。同一個測試連跑三次，三次都紅。存檔之後打的那一行「after the autosave」每次都不見，提示列每次都出現，還多存了一份備份版本。

修法只有一個判斷：讀回來的字如果跟上次存的一樣，就當作沒事。agent 動手前多寫了一段。以前 agent 把檔案寫回跟上次存檔一模一樣的內容，MarsDawn 會照樣蓋掉我還沒存的字，改完就不會了。它的理由是檔案這時其實沒變，本來就不該蓋，測試要把這個行為寫清楚。

三點三十四分修好，五點四十三分測試員回報四種組合各 69 個測試全綠，把修正拿掉，新測試又紅回去。

驗證的 agent 在這一輪抓到第二個問題。別的程式寫回同樣的字，檔案內容沒變，日期卻會跟著變。新加的判斷「當作沒事」直接返回，沒有記下新日期，下一次自動存檔一比對，發現日期不對，就失敗了，錯誤訊息說這份文件被另一個應用程式改過。五點五十二分補上這一行。七點零五分，測試員再跑一輪，全綠；只拿掉這一行，錯誤原封不動地出現。

七點十五分，驗證那邊又寫了一份結論。Codex 判了一個嚴重問題：讀檔時先讀內容、再讀日期，別的程式要是剛好在這兩步中間寫入，就會拿到舊內容配新日期，之後一存檔，對方寫的東西可能被蓋掉。負責驗證的 Claude 另外寫了一支小程式，一邊每 2 毫秒寫一次檔，一邊照同樣順序讀。讀了 32,902 次，有 227 次對不上。

那個空隙在 App 裡沒有重現。兩次讀取加起來，中位數是 43 微秒，寫入要剛好落在這幾十微秒裡，下一次存檔還得搶在 200 毫秒後的那次讀回之前。它把這條降成小問題，另開一張票，寫明這次不修。PR 說明裡原本也寫了一條已知風險，方向寫反了，它也指出來，請實作的 agent 改掉。

那時 CI 還在排隊，所以結論先寫「還不能判定」。八點二十一分 CI 綠了，改成通過，三分鐘後合進主線。

這一晚從頭到尾，沒有使用者撞到這個問題，它是規劃「把 agent 改的地方標出來」時從程式裡讀出來的。那條提示列在這 200 毫秒裡會說錯話，把我自己存的那一份算到 agent 頭上。

MarsDawn 在[作品集](https://southern-light.dev/works/)裡。

先不說了，我得去回那份計畫，六件事還在等我決定。
