CharSpin 是我做的陀螺對戰遊戲，中文名叫文字陀螺。一顆陀螺是一個字，筆畫和字體決定它的重量和轉速。對戰規則放在一個獨立的程式庫裡，調數值用的平衡工具也在那裡，讓電腦自己對打幾千場，算出虛影之間的勝率。

這個程式庫的測試，平常在我的 Mac 上跑。10 月 25 日晚上，agent 幫它多接了一台 Linux 機器：每次開 PR 或推上主線，就到一台雲端主機上再跑一遍。

第一次跑就失敗，主機找不到 Swift，路徑沒設好。補上之後第三次全綠，大約六分鐘跑完，對戰核心 516 個測試、平衡工具 43 個測試全過。那是晚上 10 點 37 分。

10 點 23 分，另一條分支上，1.4.0 的新關卡剛加了一個測試。它會把平衡工具真的執行起來，拿新詞條跑一小輪，確認工具不會半路當掉。這條分支和接 Linux 的那條是分開的，CI 那邊看不到它。那次綠燈裡的 43 個測試，沒有這一個。

新關卡隔天下午合進主線。接 Linux 的 PR 一直開著，10 月 30 日晚上 11 點 36 分才合併，掛著的綠燈還是 25 日那次。這五天主線多了新關卡，合併前沒有讓它對著新的主線重跑。合併後主線跑的第一次，紅了。

紅的只有那個新測試。它找平衡工具的方法是先找到自己在哪，再往上一層，工具應該就在旁邊。在 Mac 上，測試是資料夾裡的一個包裹，往上一層剛好是那個資料夾。在 Linux 上，回報的位置就是資料夾本身，再往上一層就走出去了。工具一直都在，測試去錯了地方，1.1 秒就失敗。

Mac 上一直是綠的。1.4.0 前後傳了三次內測版，第 37 版和第 38 版上傳前的紀錄都寫著 523 個和 44 個測試全過。Linux 那邊，從 30 日深夜那一次起，每次都紅。

做 1.4.0 那陣子，這顆紅燈先放著不修。11 月 5 日晚上 10 點 36 分，1.4.0 的發版分支合回主線，九分鐘前它自己的 Linux 檢查也還是紅的。

我說排進下一版修。10 點 38 分 agent 開了票，同一分鐘留下第一條線索：失敗在「找不到工具」那一行，看起來是找路的方法出錯，平衡工具本身沒壞，還沒實測。票上另外寫著，不要用跳過測試把它蓋掉。

五分鐘後修正的 PR 開了，只動那一個測試檔：先找回報位置的裡面，找不到再往上一層。兩個都找不到時，錯誤訊息會列出試過的兩個路徑。Linux 轉綠，那個測試這次跑了 15.6 秒，真的把工具叫起來跑完了一小輪。

負責驗證的 agent 做了兩次反向檢查。在 Linux 上拿修之前的版本跑，同一個測試 1.1 秒就紅。在 Mac 上把工具名字改成不存在的，測試也紅，訊息列出兩個路徑。它要確認的是，這個測試在該紅的時候會紅。11 點 16 分合併，主線的 Linux 測試轉綠。

同一晚另一張 PR 也被它擋了兩次。那張只是讓設定頁捲到底時多留一點空間，免得「決鬥」圓鈕蓋住版本號。它從紅著的主線開出來，Linux 跑兩次都紅，把修好的主線併進去才綠。

25 日那次綠燈，量的是那條分支當下有的東西。PR 合進來時主線已經多了一個測試，掛著的燈卻還是五天前的。

文字陀螺在[作品集](https://southern-light.dev/works/)裡。

先不說了，我得去看看還開著的那幾張 PR，它們身上的綠燈是哪一天的。
